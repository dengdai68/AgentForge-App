# 长期沟通

沟通使用独立的闭合 JSON 回复协议：仅 `reply` 必填且须为非空字符串；`handoffToAgentId` 可省略或为 null，均表示不转交。填写目标时继续校验类型及 Store 的候选成员/单次转交规则，非法目标不退化为普通回复。未知字段仍拒绝。此调整不改变任务派工/咨询协议，不需要重建原生会话；CLI 尚不覆盖长期沟通，无命令或参数变化。

未选择会话进入沟通时，列表成功加载后打开 updatedAt 最新的会话；没有会话保持空态，读取失败不猜测。显式会话选择及正在阅读的会话不因轮询排序变化而切换。

员工姓名、简介、职责、能力及插件/MCP 选择变化继续使用同一原生会话 ID；下一次调用更新系统指令和工具配置，不清除记忆。实际 Runtime 连接（Provider、可执行文件、模型或原生 profile）或会话启动目录变化才重建，明确记录原因，已保存聊天与消息游标保留。移除扩展后新调用不再启动该服务；旧历史中的工具结果不等于当前仍持有工具。

员工职责、沟通/转交规则及执行环境进入应用系统指令。当前目标只注入一次，不再发送近期聊天数组；原生会话负责历史。新外部消息按成员游标首次投递，成功保存回复后确认，失败不确认；会话重建如实记录，旧 transcript 不自动重放。详细协议见 docs/22。

控制台顶部只保留「最新」「刷新」。私聊不再重复展示唯一员工名；多成员会话在工具栏下方提供成员切换，加载更早记录也在工具栏外，原有按成员/游标查询与隔离语义不变。

沟通附件以会话为归属，原始文件保存在 `communications/<会话ID>/attachments/<附件ID>/<原文件名>`；SQLite 只保存名称、相对路径、字节数、SHA-256 和消息关联。先通过认证 HTTP 上传（单文件最多 20 MiB），再发送 attachmentIds；允许仅附件消息，引用必须属于当前会话。重名文件不覆盖，下载检查归属、路径与完整性；模型上下文只带本轮可见消息的附件位置，不把二进制内容塞入提示词。员工仍从自己的独立目录启动，提示词给出会话主目录和附件绝对位置。上传不等于已发消息，失败重试保留草稿和已上传引用。

会话列表只依据员工回复的 unreadCount 显示未读提示；人类发送、排队、失败重试均不产生未读点。读确认仍要求窗口可见且已读到消息尾部。

聊天标题栏中的控制台入口切换右侧面板，展开时从标题栏顶部到底部完整分割，聊天与控制台各占可用内容宽度一半。唯一开关始终留在左侧聊天标题栏，右侧直接展示成员选择和记录，不再重复展示控制台标题或独立收起按钮。关闭不清空草稿或阅读状态。按成员分页读取真实沟通调用，保留每次投递/尝试的关联、公开 thinking/text/tools、失败、原生会话及已脱敏提示词快照。复用任务空间控制台 renderer、内容完整性校验与按需读取；不创建虚假的 Task/Run。旧调用没有正文时如实说明，不补造内容。控制台读取和附件下载不会确认聊天已读。

本轮无新增 CLI 命令：现有 CLI 覆盖任务与配置，不覆盖长期沟通；员工/插件/MCP 配置输入、输出、帮助和 schema 不变。沟通附件与控制台通过同一认证 HTTP 提供，不扩大 CLI 权限。

沟通页支持数字员工私聊和团队群聊，历史跨任务保留。消息通过持久化投递执行，每位接收成员有自己的 Provider 会话；不同会话不会合并成一个模型上下文。

人类可选择员工或团队发消息。群聊成员按当前参与关系协作，单次转交由成员选择接收者并保留来源。项目经理协调人员与下一步安排，平台记录和投递。

会话记录支持 Markdown、未读、搜索与历史分页。侧栏只显示未读摘要；运行失败保留在对应记录中。输入草稿、阅读位置与选中会话属于界面状态。

客户端把人类发送的消息靠右、数字员工消息靠左，发送者身份来自持久消息，不按接收者推断；内容、时序、投递、未读确认和历史分页不变。正文保持左对齐，窄窗口内自然换行。

Store 拥有会话、消息和投递事实；`communication.mjs` 调用 Runtime；`communication-store.mjs` 管理状态；客户端 renderer 通过认证 HTTP 操作。

私聊/群聊共用稳定发送者配色：人类蓝色，员工按 ID（无 ID 时按名称）分配青绿或紫色。名字、加粗、引用和转交提示柔和强调；待回复和读取失败沿用信息/错误色。颜色不是新的投递/执行状态，不改变可见性、未读确认或分页。

Runtime 连接变化或旧会话缺少连接指纹时重建 Provider 会话，已保存消息仍保留。历史查询见 [员工历史](19-agent-history.md)。
